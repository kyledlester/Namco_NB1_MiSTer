# MRA format

The RBF knows nothing about any particular game. Everything game-specific
arrives through the MRA on four ioctl indices. MRAs are generated by
`scripts/mra/nb1_mra.py` from a per-game JSON description
(`scripts/mra/games/<set>.json`, MAME 0.289 metadata); do not edit them by hand.

| Index | Content | Core |
| --- | --- | --- |
| 3 | Check record (sent first) | `rtl/nb1/nb1_rom_check.sv` |
| 2 | Board record | `rtl/nb1/nb1_board_config.sv` |
| 1 | EEPROM power-on image + `<nvram index="1" size="2048"/>` | `rtl/nb1/nb1_nvram.sv`, `nb1_eeprom.sv` |
| 0 | ROM stream (`zip="<set>.zip\|namcoc75.zip"`) | `rtl/nb1/nb1_rom_loader.sv` |

The CPUs are held in reset for every download, so they never see a partly
loaded ROM or record. Indices 3, 2 and 1 come before the ROM stream, so the
EEPROM holds its final contents (the saved `.nvm`, if there is one) before
anything runs.

## Index 0: ROM stream

Every MAME region, in MAME byte order, padded to a fixed window, in platform
order. The stream offset equals the SDRAM byte address, and the same layout
serves every NB-1 game (`rtl/nb1/nb1_mem_pkg.sv`).

| Region | MAME region | Window | Offset | Nebulas Ray content |
| --- | --- | --- | --- | --- |
| OBJ (sprites) | `c355spr` | 16 MiB | `0x0000000` | 4 x (`nr1objNl` bytes 0-1, `nr1objNu` bytes 2-3) |
| CHR (tiles) | `c123tmap` | 4 MiB | `0x1000000` | `nr1-chr0..3` |
| VOICE (C352) | `c352` | 2 MiB | `0x1400000` | `nr1-voi0` |
| PROG (68EC020) | `maincpu` | 1 MiB | `0x1600000` | `nr2_mpru.13b` bytes 0-1, `nr2_mprl.15b` bytes 2-3 |
| SHAPE (tile masks) | `c123tmap:mask` | 512 KiB | `0x1700000` | `nr1-sha0` |
| C75DATA | `c75data` | 512 KiB | `0x1780000` | `nr1-spr0` (128 KiB) + fill `00` |
| C75BIOS | `namcoc75:internal` | 16 KiB | `0x1800000` | `c75.bin` |
| KEYDATA | `proms` | 32 B | `0x1804000` | `c366.bin` |

The stream ends at `0x1804020` (25,182,240 bytes). A 32-bit read at offset A
returns bytes A..A+3 with byte A in the most significant lane, the 68EC020's
order.

## Index 3: check record

Little-endian fields.

* Header, 32 bytes: `"NB1C"`, version = 1, entry count (up to 32), two zero
  bytes, expected index-0 stream length (u32), 20 zero bytes.
* Entry, 32 bytes: region id (u8), lanes (u8: 1, 2 or 4), two zero bytes,
  offset (u32, multiple of 4), length (u32, multiple of 4), one CRC32 per
  lane (4 x u32), four zero bytes.

Byte k of a longword (k = 0 is the most significant) belongs to lane
k * lanes / 4, so the CRC of each lane of an interleaved region equals the
CRC32 MAME lists for that EPROM file. Fill areas carry the CRC of the fill.
After every download and reset the core reads the regions back and compares.

## Index 2: board record

16 bytes, little-endian:

| Byte | Field |
| --- | --- |
| 0-3 | `"NB1B"` |
| 4 | version (1 or 2) |
| 5 | record length = 16 |
| 6-7 | 0 |
| 8 | KEYCUS mode: 0 = no KEYCUS (every word reads `$0000`), 1 = ID word + changing word |
| 9 | KEYCUS ID word index (0-15; address `$6E0000 + 2 * index`) |
| 10-11 | KEYCUS ID value (the part number, e.g. C366 = `$016E`) |
| 12 | KEYCUS changing-word index (0-15) |
| 13 | version 2: the game's MAME orientation in quarter turns clockwise (0 = ROT0 ... 3 = ROT270) |
| 14-15 | 0 |

The fields are taken only when the whole record has arrived and is valid. With
no record or an invalid one, the KEYCUS answers `$0000` and the game's own
protection check fails visibly. Nebulas Ray:
`4E 42 31 42 02 10 00 00 01 03 6E 01 07 01 00 00` (C366 on word 3, changing
value on word 7, ROT90). The values come from MAME's `custom_key_r`.

## Index 1: EEPROM

2 KiB (a 28C16). The MRA sends an erased image (`FF` x 2048). MiSTer then
replaces it with the saved `.nvm` if one exists, and saves the EEPROM again
after the game writes it. The file layout is MAME's `nvram/<set>/eeprom`
(cell 0 first).
